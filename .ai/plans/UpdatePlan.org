* Executive Summary

Eldr is a minimal Rack-based micro-framework (~8 lib files, ~500 LOC) last
touched in March 2015. It is pinned to Ruby 2.1.5 and a stack of 2014-era
dependencies (Rack 1.6, mustermann 0.4, rspec 3.1, rubocop 0.28). On the
current toolchain (Ruby 3.4, Bundler 2.6) the project will not even =bundle
install=, because the =Gemfile= hard-codes =ruby '2.1.5'=.

Modernizing it requires three intertwined migrations:

  1. *Ruby 2.1 -> 3.x* — most importantly the Ruby 3.0 keyword-argument
     separation, which silently breaks the core route-adding API
     (=Route.new(hash)=, =add({...})=).
  2. *Rack 1.x -> 3.x* — a major rewrite: headers must be lowercase,
     bodies must be enumerables (no bare =Array/String= body),
     =Rack::MockRequest= / =Rack::MockResponse= were removed, and
     =Rack::Builder= internals changed.
  3. *mustermann 0.4 -> 4.x* — API and default type changes for the route
     matcher.

The plan below is phased so that each step is independently verifiable,
ends with a green test run, and never leaves the repo in a broken state.
The end state is: eldr runs on Ruby 3.4+, Rack 3.2, mustermann 4.0, with a
modern rspec/rubocop stack, 100% of the existing behavior covered by an
expanded test suite, and CI on GitHub Actions.

* Goals & Non-Goals

** Goals
- G1. The gem installs and runs cleanly on Ruby 3.1, 3.2, 3.3, 3.4.
- G2. All existing example apps (the =.ru= files) behave identically
     after migration, verified by the example specs.
- G3. All existing unit specs pass without modification of intent.
- G4. Test coverage is expanded to close gaps (Configuration edge
     cases, Builder URLMap path, Cascade, error-as-response paths).
- G5. RuboCop runs clean under a modern config; lints enforced in CI.
- G6. CI runs on GitHub Actions for the supported Ruby matrix.
- G7. Public API (the DSL in =Eldr::App=) is preserved; any breaking
     change is documented in a CHANGELOG and the README.

** Non-Goals
- A rewrite (we keep the architecture and the DSL).
- Adding new features (templates, ORM, etc.) — only modernization.
- Reaching Sinatra parity; eldr stays minimal.
- Supporting Rack 2 in parallel — single target = Rack 3.

** Phase 1 — Ruby 3.x keyword-argument compatibility
This is the single highest-risk correctness bug and it is invisible:
the route DSL appears to work but silently mis-handles kwargs.

Affected call sites (exhaustive):

- =lib/eldr/app.rb= :: =Route.new(route_attributes)=
     -> change to =Route.new(**route_attributes)=.
- =lib/eldr/app.rb= :: the per-verb DSL =add({ verb: ..., path: ...,
     handler: ... }.merge!(options))=
     -> change to =add(**{ verb: ..., path: ..., handler: ... }.merge!(options))=
     (or build the hash then =add(**h)=).
- =lib/eldr/app.rb= :: =add= signature is =def add(verb: :get,
     **route_attributes)= — already keyword-only; keep, but ensure all
     callers splat.
- =lib/eldr/route.rb= :: =def initialize(verb: :get, path: '/', name:
     nil, order: 0, handler: nil, to: nil)= — keyword-only. Verify all
     spec/example call sites pass keywords (they do: =Route.new(name:
     :cats)= etc.).
- =lib/eldr/app.rb= :: =inherited(base)= calls
     =base.builder.use builder.middleware= — fine.
- =lib/eldr/app.rb= :: =call= / =call!= — no kwargs.
- =lib/eldr/app.rb= :: =before(*keys, &block)= — note the
     =*keys = [:all] if keys.empty?= idiom works but is odd; consider
     =keys = [:all] if keys.empty?=. (Not a correctness bug; style.)

Guard rail: add a focused spec in =spec/app_spec.rb= that registers a
route via the block DSL with an options hash (=get '/x', name: :foo do
... end=) and asserts the route is created with =name == :foo=. This is
the regression test that would have caught the original Ruby 3 break.

Checkpoint: =bundle exec rspec= — unit specs green (Rack::MockRequest
still available under Rack 2.2 bridge).

** Phase 3 — Rack 1.x -> Rack 3.x
This is the largest phase. Break it into sub-steps, each green.

- [X] Audit every response triple in =examples/*.ru= and the lib:
      - Headers must be lowercase strings (Rack 3 enforces this;
        =Eldr::Cascade::NOTFOUND= uses ='CONTENT-TYPE'= -> fix to

* Test Strategy

** Layers
1. *Unit specs* (=spec/<class>_spec.rb=) — pure Ruby, no network. These
   are the regression net for the Ruby-3 and Rack-3 migrations. They must
   never depend on a real HTTP server.
2. *Example specs* (=spec/examples/*=) — load each =.ru= via
   =Rack::Builder.parse_file= and drive it with =Rack::Test::Session=.
   These prove the end-to-end Rack contract under Rack 3.
3. *README contract* (=spec/readme_spec.rb= + =readme_definitions.yml=)
   — keep green; only touch =readme_definitions.yml= if README
   structure intentionally changes.

** Order of proof
- After Phase 1: unit specs green (Ruby 3 kwargs fixed).
- After Phase 3: example specs green (Rack 3 contract).
- After Phase 6: new specs green; coverage >= 95%.
- After Phase 8: CI green on matrix 3.1–3.4.

** Regression guards to add (the bugs we most fear regressing)
- =spec/app_spec.rb= :: kwargs DSL registration (Phase 1).
- =spec/builder_spec.rb= :: =map= + =URLMap= nested mounting (Phase 3/6).
- =spec/cascade_spec.rb= :: 404-then-200 ordering, lowercase headers (Phase 6).
- =spec/app_spec.rb= :: =throw :pass= deferral across two routes (already
  exists; keep).

  author code, not user input).

  has no example (open TODO). Phase 7 + 6.11 close both.
  *Resolved:* =lib/eldr.rb= eagerly requires cascade + version and
