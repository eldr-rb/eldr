** Phase 1 — Close the builder.rb line gaps (spec/builder_spec.rb)

*** Test 1.1: =#use= after =#map=

Covers line gap 1 (=builder.rb:28–30=) plus branch gaps 3 and 5
(=builder.rb:27= then; =builder.rb:65= then, since the pending map is
converted into a proc that calls =generate_map= with the built app as
=default_app=).

Add after the existing =describe '#use'= block:

#+begin_src ruby
describe '#use after #map' do
  subject(:app) { builder.to_app }

  let(:middleware) do
    Class.new do
      def initialize(app)
        @app = app
      end

      def call(env)
        status, headers, body = @app.call(env)
        [status, headers.merge('x-mw' => '1'), body]
      end
    end
  end
  let(:index) { proc { |_env| [200, { 'content-type' => 'text/plain' }, ['index']] } }
  let(:cats)  { proc { |_env| [200, { 'content-type' => 'text/plain' }, ['cats']] } }
  let(:builder) do
    cats_app = cats
    b = described_class.new
    b.map '/cats' do
      run cats_app
    end
    b.use middleware
    b.run index
    b
  end

  it 'wraps the default app in the middleware and mounts it at /' do
    expect(app).to be_an_instance_of(Rack::URLMap)
    resp = app.call(Rack::MockRequest.env_for('/', method: :get))
    expect(resp[2]).to eq(['index'])
    expect(resp[1]['x-mw']).to eq('1')
  end

  it 'routes mapped paths to their own apps, bypassing the middleware' do
    resp = app.call(Rack::MockRequest.env_for('/cats', method: :get))
    expect(resp[2]).to eq(['cats'])
    expect(resp[1]['x-mw']).to be_nil
  end

  it 'consumes the pending map' do
    app
    expect(builder.instance_variable_get(:@map)).to be_nil
  end
end
#+end_src

Behavior pinned by this test (current semantics, worth knowing):
- =use= consumes the pending map and prepends a map-generating proc to
  the middleware stack; =to_app= then builds =Rack::URLMap= with
  ='/' => middleware-wrapped default app=.
- Middleware applied after =map= wraps *only* the default (run) app;
  mapped blocks that call =run= themselves bypass it.

**** Implementation gotcha (verified the hard way)

=Builder#initialize= =instance_eval=s blocks, and mapped blocks are
later =instance_eval=ed on a *fresh* =Builder= inside =generate_map=
(=builder.rb:66=). Inside those blocks =self= is the Builder, so
RSpec =let=/=subject= helpers are NOT visible — reference =cats=
directly inside the map block and you get =NameError=. Capture the
value into a local first:

#+begin_src ruby
cats_app = cats
b.map '/cats' do
  run cats_app
end
#+end_src

*** Test 1.2: =#warmup=

Covers line gap 2 (=builder.rb:41=) plus branch gap 4 (=builder.rb:54=
then — the warmup actually runs). Both the block and proc argument
forms are exercised (=prc || block=).

#+begin_src ruby
describe '#warmup' do
  let(:inner) { proc { |_env| [200, {}, ['ok']] } }

  it 'invokes the warmup block with the built app' do
    seen = nil
    builder = described_class.new
    builder.warmup { |app| seen = app }
    builder.run inner
    expect(builder.to_app).to eq(seen)
  end

  it 'accepts a proc argument' do
    seen = nil
    builder = described_class.new
    builder.warmup(proc { |app| seen = app })
    builder.run inner
    expect(builder.to_app).to eq(seen)
  end
end
#+end_src

** Phase 2 — Close the app.rb branch gaps (spec/app_spec.rb)

*** Test 2.1: named after-filters attach to matching routes (app.rb:107)

Add to =describe '.add'= (asserts both attachment and execution):

#+begin_src ruby
it 'attaches named after filters to routes with a matching name' do
  ran = []
  bob = Class.new(described_class)
  bob.after(:cats) { ran << :after_cats }
  bob.get '/cats', name: :cats do
    [200, {}, ['meow']]
  end
  env = Rack::MockRequest.env_for('/cats', method: :get)
  bob._new.call!(env)
  expect(ran).to eq([:after_cats])
end
#+end_src

The existing =describe '.after'= specs only assert *registration*
(=after_filters[:cats].length=); no route named =:cats= is ever defined
alongside them, so the attachment line's then-branch never ran. This
closes it and guards the symmetry with =before= (which is already
covered end-to-end via =examples/app.ru=).

*** Test 2.2: re-raise non-callable errors (app.rb:138)

Add as a sibling of the existing =context 'when raising an error'=
(under =describe '#call!'=):

#+begin_src ruby
it 're-raises errors that do not respond to #call' do
  bob = Class.new(described_class)
  bob.get '/boom' do
    raise 'boom'
  end
  env = Rack::MockRequest.env_for('/boom', method: :get)
  expect { bob._new.call!(env) }.to raise_error(RuntimeError, 'boom')
end
#+end_src

The existing error spec uses a callable =Error= class (→ 500 response);
this pins the other side of the =unless=: plain errors propagate to the
server/Rack, as intended.

** Phase 3 — Close the matcher.rb branch gap (spec/matcher_spec.rb)

*** Test 3.1: non-String/Regexp paths (matcher.rb:20, implicit else)

Add to =spec/matcher_spec.rb= (e.g. after the =regex paths= describe):

#+begin_src ruby
it 'returns a nil handler for paths that are neither String nor Regexp' do
  expect(described_class.new(:cats).handler).to be_nil
end
#+end_src

*Decision point:* this documents rather than validates — =Matcher= with
an unsupported path type silently yields a nil handler (and a later
=NoMethodError= on =match=). The coverage-friendly alternative is to
raise =ArgumentError= in the else arm, but that is a behavior change and
out of scope for this plan. Default: test as-is; file a TODO for the
=ArgumentError= refactor (see Risks).

** Phase 4 — Ratchet the gate (spec/spec_helper.rb)

#+begin_src ruby
if ENV['COVERAGE']
  require 'simplecov'
  SimpleCov.start do
    add_filter '/spec/'
    add_filter '/examples/'
    add_group 'lib', 'lib'
    enable_coverage :branch
    SimpleCov.minimum_coverage line: 100, branch: 100
  end
end
#+end_src

Verified with SimpleCov 1.1.1 on [2026-10-11]:
- At 251 / 251 + 57 / 57 the run exits 0.
- Below the minimum (baseline 247 / 251) it exits 2 and prints
  "Lowest-coverage files" per metric — a self-explanatory CI failure.

Notes:
- =minimum_coverage= accepts the =line:=/=branch:= hash on SimpleCov
  1.x; =enable_coverage :branch= is required for branch tracking. Branch
  coverage relies on Ruby's built-in branch instrumentation (Ruby ≥ 2.5)
  — CI's 3.1–3.4 matrix is fine.
- CI needs *no workflow change*: the =COVERAGE=1 bundle exec rspec= step
  now fails on any regression. (Optional nicety: swap it for
  =make coverage= to keep report/uncovered output on failure.)
- Makefile needs no change; =simplecov uncovered= prints nothing once
  every file is at 100%.
- Optional cleanup while touching this block: =add_group= is deprecated
  (SimpleCov emits a deprecation warning) in favor of
  =SimpleCov.group= — same arguments.

* Risks & Notes

1. *use-after-map semantics.* The new builder test pins current
   behavior: middleware applied after =map= wraps only the default app,
   and mapped blocks bypass it. If that is judged a bug (upstream
   =Rack::Builder= gives =map= its own scope), the fix belongs in a
   separate behavior-change PR with its own test updates — this plan
   deliberately documents as-is.
2. *Matcher nil handler.* The =matcher.rb:20= else branch is degenerate
   input. We document (nil handler) rather than change; raising
   =ArgumentError= is the cleaner long-term behavior and is noted as a
   follow-up decision.
3. *Instance-eval gotcha in builder specs.* Any spec that puts =let=
   references inside =map= blocks will fail with =NameError= (see
   Phase 1 gotcha). Capture into locals first. This cost one
   debugging round during plan validation.
4. *RuboCop RSpec cops.* =ExampleLength= (15) and =MultipleExpectations=
   (3) forced the use-after-map verification to be split into three
   examples; the sketches in this plan already conform (verified with
   =rubocop=). Distributing them into the existing spec files also
   avoids =RSpec/MultipleDescribes=.
5. *Gate failure mode is loud but clean.* Below the minimum SimpleCov
   exits 2 and prints lowest-coverage files per metric — CI logs will
   point directly at the regressing file.
6. *Numbers are stable.* Line totals: 251 relevant (222 omitted);
   branch totals: 57. The suite grows 119 → 127 examples. Runtimes
   stay well under a second locally.
